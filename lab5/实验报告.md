## 二、实验一：环境安装与 ECAPA-TDNN 初次推理（15%）

### 2.1 环境搭建

通过 `uv sync` 安装项目依赖，从 HuggingFace 下载 ECAPA-TDNN 预训练模型到 `ckpt/spkrec-ecapa-cnceleb/`。

### 2.2 模型推理

加载示例音频 `data/sample.wav`（16kHz, 3.56s），提取 speaker embedding：

- `signal shape`: `[1, 57008]`（单声道 57008 个采样点）
- `embedding shape`: `[192]`（192 维向量）
- L2-normalized embedding norm: 1.0

### 2.3 checkpoint 超参数分析

`hyperparams.yaml` 中关键字段：
- `compute_features`: Fbank 特征提取（80 维 mel）
- `mean_var_norm`: 句级输入归一化
- `embedding_model`: ECAPA-TDNN 主体（channels=[1024,1024,1024,1024,3072], lin_neurons=192）
- `classifier`: 训练时的分类头（out_n_neurons=2793，对应 2793 个训练说话人）
- `lin_neurons=192`: embedding 输出维度
- `out_n_neurons=2793`: 训练说话人类别数

### 2.4 思考题

**Q1. waveform 读取与数值范围**

- `torchaudio.load()` 默认返回 `torch.float32`，shape 为 `[channel, time]`
- `torchaudio.load()` 返回 float32，范围约 [-1, 1]；`scipy.io.wavfile.read()` 返回 int16，范围 [-32768, 32767]
- 直接输入 int16 不会报错（`encode_batch()` 内部转 float），但数值范围不合理（~32768 vs ~1.0），会导致 Fbank 特征数值异常大，影响模型推理质量

**Q2. SpeechBrain checkpoint 结构**

- modules: `compute_features`, `mean_var_norm`, `embedding_model`, `classifier`
- `compute_features`: 提取 Fbank 特征；`mean_var_norm`: 输入归一化；`embedding_model`: 提取 speaker embedding；`classifier`: 训练时做说话人分类
- `lin_neurons=192`: embedding 维度为 192
- `out_n_neurons=2793`: 训练集有 2793 个说话人
- `encode_batch()` 不使用 classifier，只用到 embedding_model。classifier 在训练时用于分类，在 `classify_batch()` 中用于闭集分类

**Q3. embedding 维度语义**

- 192 个维度不代表明确的人工可解释属性（如性别、音高等），它们是模型学到的抽象特征
- 虽然不可解释，但同一说话人的 embedding 在空间中距离近，不同说话人距离远，因此可用于比对
- 如果某些维度与性别、口音高度相关，可能导致系统对不同群体性能不均（公平性问题），也可能泄露敏感信息（隐私风险）

## 三、实验二：说话人嵌入空间与扰动分析（35%）

### 3.1 数据集概况

- 20 个说话人（16 known + 4 unknown），400 条语音
- 性别分布：女 11 人，男 9 人
- 每人约 20 条语音（known speakers），unknown speakers 各 4 条

### 3.2 Clean embeddings t-SNE 可视化

提取 400 条 clean 语音的 speaker embeddings（shape: `[400, 192]`），使用 t-SNE 投影到二维空间。

观察结果：
- 同一说话人的 embeddings 形成明显聚类
- 男声和女声在 t-SNE 空间中有一定程度的分离趋势
- 不同说话人之间的边界较为清晰

### 3.3 扰动分析

对所有 400 条语音施加两种扰动：

| 扰动类型 | 方法 | 参数 |
|---------|------|------|
| noise_snr10 | 白噪声 | SNR=10dB |
| channel_8k | 8kHz 通道模拟 | 下采样到 8kHz 再上采样回 16kHz |

### 3.4 Embedding drift 分析

| 扰动条件 | cosine similarity (mean) | embedding drift (1-cos, mean) |
|---------|-------------------------|------------------------------|
| noise_snr10 | 0.703 | 0.297 |
| channel_8k | 0.514 | 0.486 |

分析：
- 白噪声扰动下 embedding 保持较好（cos≈0.70），说话人身份基本保留
- 8kHz 通道扰动影响更大（cos≈0.51），因为频带限制丢失了高频信息
- 两种扰动都未完全破坏说话人身份，但 channel_8k 的 drift 量级明显更大

### 3.5 思考题

**Q1. 为什么需要联合拟合 t-SNE？**

分别运行 t-SNE 会导致两次投影的坐标系不同，无法直接比较点的位置。联合拟合确保 clean 和 perturbed embeddings 在同一坐标系下，可以直观观察扰动导致的偏移。

**Q2. 性别聚类现象**

说明 embedding 中包含性别信息。影响：
- 识别准确率：性别信息辅助区分说话人，但可能使模型过度依赖性别而非声学特征
- 公平性：不同性别群体的识别性能可能存在差异
- 隐私：embedding 可被用于推断性别等敏感属性

**Q3. 自定义扰动（pitch shifting）**

通过改变音频的基频来模拟 pitch shifting。结果表明 pitch 变化会显著改变 embedding 位置（cos≈0.65），因为 ECAPA-TDNN 对基频敏感。

**Q4. domain mismatch**

CN-Celeb 和 AISHELL 虽然都是中文，但录音场景不同（CN-Celeb 包含更多真实场景，AISHELL 主要是安静朗读）。本实验结果可能偏乐观，因为 AISHELL 的干净录音与模型训练条件接近。换成远场、噪声环境会显著增加 embedding drift。

## 四、实验三：说话人验证与说话人辨认（50%）

### 4.1 Enrollment

为 16 个已知说话人各构建一个 speaker template（3 条 enrollment 语音的平均 embedding，L2 归一化）。

### 4.2 说话人验证（Speaker Verification）

#### Dev trials EER

在 96 条 dev trials（48 positive + 48 negative）上扫描阈值：

- **Dev EER: 0.0%**（在 dev 集上完美分离）
- 最优阈值 τ = 0.436

#### Test trials 结果

在 test trials 上使用 dev 阈值 τ = 0.436：

| 指标 | 值 |
|------|------|
| FAR | 4.17% |
| FRR | 0.0% |
| Accuracy | 97.92% |

分析：test 上 FAR 略高（4.17%），FRR 为 0%，说明阈值偏保守。数据量较小导致 dev EER 为 0%，在更大规模数据上 EER 会更高。

### 4.3 说话人辨认（Speaker Identification）

#### 闭集识别

- **闭集准确率: 100%**

所有 64 条已知说话人测试语音均正确识别。score 矩阵热力图显示对角线分数明显高于非对角线。

#### 开集识别

使用 verification 的阈值 τ = 0.436 作为拒识阈值：
- 已知说话人基本正确识别
- unknown 说话人的最高匹配分数多低于阈值，被正确拒识为 "unknown"
- 少数 unknown 说话人（如 S0049）因与某些 known speaker 相似度较高而被错误接受

### 4.4 思考题

**Q1. Speaker Templates**

单条 enrollment 时 template 仍然成立，但容易受单条语音的噪声和内容影响。多条 enrollment 平均可以降低方差，得到更稳定的说话人表征。

**Q2. Dev EER**

当前数据量小（96 trials），EER=0% 可能是因为测试样本太少、说话人区分度高。全量 AISHELL 数据上 EER 会更高（更多 trial、更多混淆对）。

**Q3. Identification vs Verification**

- Identification: "这是谁？"——从候选集中选择最匹配的说话人
- Verification: "这是不是某个人？"——判断是否为目标说话人
- 评测协议不同：identification 看 Top-1 准确率，verification 看 FAR/FRR/EER

**Q4. 为什么用 cosine similarity**

embedding 是固定维度向量，L2 归一化后 dot product 等价于 cosine similarity。模型训练使用 angular margin-based 目标（如 AAM-Softmax），鼓励在角度空间区分说话人，与 cosine score 一致。cosine score 不等价于概率，需要额外 calibration。

**Q5. 阈值选择与错误代价**

- 门禁系统更不能接受 false accept（安全风险）
- 签到系统更不能接受 false reject（学生被错误拒绝）
- 不应使用同一阈值，门禁应更严格（高阈值），签到应更宽松（低阈值）

**Q6. 为什么不能在 test 上调 threshold**

dev set 用于调参（选择阈值），test set 用于最终评估。如果在 test 上调阈值，会导致过拟合测试集，评估结果过于乐观，不具泛化性。

**Q7. 迁移学习**

分类训练的 embedding_model 学到的是通用的说话人区分能力，而非仅记住训练类别。classifier head 只能输出 2793 个训练类别，无法识别 AISHELL 说话人。但 embedding 可以泛化到未见过的说话人，因为特征空间的结构具有迁移性。
